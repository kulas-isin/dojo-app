# 🐾 PawDojo 產品路線圖 / Roadmap

> 這份文件記錄產品願景與待實作的想法，會持續更新。目前狀態：**v0.1 MVP 已可遊玩（網頁版）**。

## 願景
一個邊遛狗、邊散步邊玩的娛樂 App：在地圖上建立/挑戰寵物道館，用照片影片對戰，
同時具備**公益性質**（幫助流浪動物）與**養成/對戰的遊戲性**。

---

## 現況 v0.1（已完成）
- 地圖看/建道館（原生地圖 + Web 示意地圖）
- 上傳貓狗照片/影片挑戰衛冕者
- 社群投票對戰、結算換衛冕者
- 全域排行榜、個人頭銜與戰績
- 資料存在裝置本機（AsyncStorage），**尚無跨用戶共享**

## Pillar A — 設計系統升級 🎨
**目標**：從「emoji 到處貼」升級成一致、好看、可維護的設計系統。

> **現況 & 回饋（2026-06）**：Phase 1 已導入 Claude 溫暖亮色系 + Lucide 圖示、
> 建立 tokens 與風格指南。使用者滿意度約 **30/100** — 方向可接受但要再打磨。
> **決策：先不深追設計，MVP 功能優先，設計之後再改。**
>
> **未來目標視覺方向：插圖風格（Illustration）** 🖌️
> - 想要手繪／插畫感的視覺，而非目前的線條圖示 + 純色卡片。
> - 待探索：整體插畫風（角色、道館、背景皆插圖化）、色調、
>   是否與 Pillar C 的 2D 像素寵物風格統一或分開。
> - 執行方式待定：自訂插圖素材庫 / 插畫風 icon set（如 Streamline、Open Doodles、
>   Blush 等開源或授權素材）/ 委託繪師。可先做一頁情緒板（mood board）再定案。

- **視覺風格**：改採「Claude / Anthropic 風格」——溫暖、簡約、留白多、
  暖珊瑚（clay/coral）主色、乾淨字體。（風格方向待確認，見下方問題）
- **圖示**：用開源 icon set 取代 emoji。建議 **Lucide**（MIT 授權、線條簡約、
  有 `lucide-react-native`）。道館/寵物類型/分頁/按鈕都改用向量圖示。
- **設計 Tokens**：把顏色、間距、圓角、字級整理成 tokens（已有雛形於 `src/theme.ts`），
  擴充成完整設計系統，UI 元件統一走 tokens。
- **Figma 設計稿**：使用者希望保留可用 Figma 修改的設計稿。
  ⚠️ 技術限制：我無法直接產生原生 `.fig` 檔。可行方案（待選）：
  1. 用程式建立設計系統 + 一份**線上風格指南（Style Guide）頁面**，
     再以 Figma 外掛「html.to.design」匯入 Figma 編輯。
  2. 產出 SVG 元件與 icon，匯入 Figma。
  3. 提供完整設計規格（tokens/元件/間距），由設計師在 Figma 重建。

## Pillar B — 公益：流浪浪浪 🏠
**目標**：讓 App 有公益意義，協助辨識與記錄流浪動物。

- **流浪道館**：可為流浪貓狗聚集地建立道館，並**標記為「流浪」**，地圖上有明顯區別
  （不同顏色/圖示/邊框）。
- **浪浪檔案（IG 式）**：每隻流浪動物有自己的檔案頁：
  - 主頁：頭像、暱稱、地點、狀態（已結紮 / 待認養 / 已認養…）、追蹤數
  - 照片牆（grid）：點任一張進**大圖檢視**，可左右滑看更多
  - 生活日記：貼文（照片 + 文字），像 IG 動態
- **多人協作記錄**：附近的人都能幫同一隻浪浪補充照片/近況（需帳號 + 後端）。

---

## Pillar C — 養成與對戰 🎮
**目標**：在投票之外，加入更深的遊戲性。

- **捏臉/寵物 Avatar**：使用者捏出自己的寵物角色。風格未定，傾向 **2D 像素風**。
  - 部位選擇（耳朵/花色/眼睛/配件…）、色盤、預覽。
- **「我的空間」放置型玩法**：捏出的動物住在一個小空間裡活動，
  隨時可進去觀察（像放置型手遊）。
- **道館空間模型**：道館內能看到這些角色在場景中走動/互動。
- **屬性對戰系統**：類寶可夢——角色有**屬性**與**招式/攻擊**，
  回合制對戰，勝負影響道館衛冕，而不只是比票數。

## 🔧 關鍵技術考量
> 上述大部分功能都需要**真正的後端**，因為要跨用戶共享資料（別人也看得到浪浪、對戰、排行）。

1. **後端 / 資料庫**：目前是純本機。要做公益紀錄、跨用戶對戰、真排行，
   需要後端。建議 **Supabase**（Postgres + 雲端儲存 + 帳號，免費額度夠原型）
   或 Firebase。
2. **帳號系統**：多人協作、對戰、留存都需要登入（Email / Google / Apple）。
3. **媒體儲存**：照片/影片要雲端儲存（Supabase Storage / Cloudinary）。
4. **即時對戰**：屬性對戰若要即時對打，需要 realtime channel；
   單機/非同步對戰則較單純。
5. **打包 iOS App**：核心是 Expo，未來用 EAS Build 出 iOS/Android，不需重寫。

## 🗺️ 建議分期（草案，順序待討論）
- **Phase 1 — 設計系統 + 圖示**（純前端、低風險、馬上有感）
  導入 Lucide、建立 tokens/元件、風格指南頁。
- **Phase 2 — 後端 + 帳號**（基礎建設，後面所有功能的地基）
  Supabase 專案、資料表、登入、把現有道館/作品搬上雲端。
- **Phase 3 — 流浪浪浪紀錄**（公益 Pillar B）
  流浪標記、浪浪檔案頁、照片牆/大圖、生活日記。
- **Phase 4 — 捏臉 Avatar + 我的空間**（養成）
- **Phase 5 — 屬性對戰系統**（最複雜，放最後）
